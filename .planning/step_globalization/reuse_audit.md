## Reusable pieces for a tiny direct-step layer

`apply_joint_gradient(model, optimizer, joint_gradient)` (`lap_moo_training.py:240`) is the narrow commit point: it assigns grads, calls one `optimizer.step()`, and returns actual per-parameter deltas. `train_moo_update(...)` (`:266`) currently owns the whole sequence: it zeroes grads, computes/all-reduces tasks, calls the aggregator, applies the optimizer, then advances the scheduler. A future scalar step control belongs after aggregation and before `apply_joint_gradient`; the current function has no dry-run or `step_scale` argument. For the diagnostic’s plain SGD (one group, no momentum/decay/scheduler), set the commit LR to `alpha*LR` and call the apply path once after selecting alpha. Advance EMA and scheduler once, after acceptance. `record_update_geometry=False` is not a dry-run; it still mutates model and optimizer.

For a later adaptive optimizer, scale the optimizer’s proposed *parameter delta*, not its input gradient: Adam/RAdamW preconditioning means scaling `joint_gradient` does not preserve a same-direction trial ray. An optimizer proposal step mutates moments/state, so evaluating it repeatedly requires full optimizer rollback or a proposal/commit split; neither exists today. Keep that separate from the SGD T2 test.

## Mutation and rollback risks

`train_moo_update` is unsuitable inside the alpha loop: each call clears/sets `.grad`, steps parameters and optimizer state, returns a new PCD EMA state, and calls `scheduler.step()` if supplied. The CLI then commits the returned EMA and may checkpoint the cursor (`train_lap_moo.py:828–902`). Do not trial by repeated calls. The external control avoids this by using stateless SGD and has no checkpoint/scheduler.

There is no generic in-memory transaction helper. `capture_rng_state()` / `restore_rng_state()` (`lap_moo_training.py:461,470`) preserve Python, NumPy, CPU Torch, and all CUDA RNG state. `_seed_process(41)` (`train_lap_moo.py:254`) also enables deterministic algorithms. Keep the external script’s `model.train()` mode consistent; if a future objective consumes randomness, restore RNG before each candidate. For a future optimizer-backed trial, a safe rollback bundle must include model buffers as well as parameters, optimizer state, scheduler state, RNG, and the pre-update aggregator state.

`save_moo_checkpoint` / `load_moo_checkpoint` (`lap_moo_training.py:622,681`) are exact resume helpers, not lightweight candidate snapshots: they validate protocol, manifest, cursor, PCD state and DDP world size; load mutates model/optimizer/scheduler/RNG. `load_lap_checkpoint` (`lap_checkpoint.py:117`) restores the predopt model only. Neither supplies the missing pre-index-1 snapshot from the external receipt.

The first curve should stay single-rank, matching the prior script. In DDP, `average_raw_task_gradients` requires all ranks to enter matching collectives after zero materialization, and candidate acceptance must use globally averaged task losses (`_average_task_losses`, private helper at `lap_moo_training.py:228`) with every rank evaluating the same alpha sequence. There is no public candidate-loss all-reduce helper.
